Diff Algorithm Performance

Internal learning doc · May 2026 · crates/diff-core

TL;DR: Replaced the entire diff backend — dropped similar crate entirely in favor of imara-diff. On the pathological 200K-line churn case: 64,056 ms → 547 ms end-to-end (117×), and in raw micro-benchmark: 63,100 ms → 11 ms (5,800× speedup). All three algorithms (Myers, Patience, Histogram) are now backed by imara-diff.

1. The Problem

The synthetic perf suite revealed a pathological case: many-small-lines-churn — 200,000 lines where every other line is modified ("0", "1-x", "2", "3-x", …). The initial baseline with similar::Myers clocked in at ~64 seconds.

3. Algorithm Journey

3.1 Attempt 1: similar::Patience — 76s ✗

similar's Patience was worse than Myers (76s vs 64s). Patience is O(N log N) on unique lines but degrades when every line is unique — the LCS table overhead dominates.

3.2 Attempt 2: imara-diff::Histogram — 33s 1.94×

imara-diff's Histogram improved to 33s — a meaningful 1.94× speedup. We set Histogram as the new default, matching git diff's behavior.

3.3 Attempt 3: imara-diff::Myers — 0.5s 117× end-to-end

Then we benchmarked imara-diff's Myers implementation in a raw micro-benchmark (no I/O, no process overhead, just the diff computation):

🔬 Raw micro-benchmark (200K lines, 50% churn): 
                     similar::Myers      imara-diff::Myers     Speedup
                     ──────────────      ─────────────────     ───────
Tokenize             (internal)           8.4 ms
Diff compute         63,087 ms            1.7 ms              37,000×
Hunk collection        (~13 ms)           0.4 ms                33×
─────────────────────────────────────────────────────────────────────
Total                   63,100 ms           10.5 ms            ~5,800×
The 5,800× speedup is not algorithmic — both are O(ND) Myers. It's an implementation-quality difference. imara-diff uses the linear-space variant with middle-snake optimization, a custom interned token representation that avoids repeated string hashing, and a more efficient edit-graph traversal. similar's Myers, by contrast, builds the full O(N²) dynamic-programming table in the worst case.

The end-to-end perf suite shows 547 ms (117× faster than similar's 64,056 ms) — the difference from the raw 10.5 ms is process startup, file I/O, and the JS perf harness overhead.

5. Key Learnings

  1. Profile first. Intuition said intraline spans or hunk building might be slow — they weren't. The diff engine was 99.94% of the cost.
  2. Implementation quality matters more than algorithm class. Both similar and imara-diff implement the same Myers O(ND) algorithm, but imara-diff is ~5,800× faster on pathological input. The linear-space variant with middle-snake optimization in imara-diff makes a night-and-day difference.
  3. Patience ≠ fast. Patience is O(N log N) on unique lines, but when every line is unique the LCS table overhead dominates. It was slower than Myers.
  4. Histogram has its place. For files with many repeating lines (whitespace-ignored diffs, minified code), Histogram's frequency pruning gives it an edge. It also produces git diff-compatible output — important for tooling compatibility. Keep it available as an option.
  5. Drop dead dependencies aggressively. Once imara-diff proved faster for every algorithm, removing similar entirely was the right call. Zero regrets.

6. Architecture (Current)

pub enum DiffAlgorithm {
    #[default]
    Myers,      // imara-diff::Algorithm::Myers (547 ms on pathological)
    Patience,   // mapped to imara-diff::Algorithm::Histogram
    Histogram,  // imara-diff::Algorithm::Histogram (git-compatible)
}

All three variants route through a single build_changes_imara() function that adapts imara-diff's Sink/Hunk-based output into our Vec<LineChange> model. Patience is mapped to Histogram internally since imara-diff doesn't provide a standalone Patience (and both are LCS-based).

The --deadline <ms> flag runs the diff on a background thread with recv_timeout, returning empty results with a warning if the budget is exceeded.

7. Summary of Changes

  • Replaced similar with imara-diff: removed similar from workspace and diff-core dependencies.
  • Myers is the default (imara-diff): 547 ms on pathological case, down from 64,056 ms with similar.
  • Histogram available via --algorithm histogram: 32s on pathological, but git-compatible output.
  • Patience mapped to Histogram: documented limitation; imara-diff only provides Myers and Histogram.
  • --deadline <ms> flag: best-effort diff with time budget for interactive use cases.
  • 172 tests pass, zero warnings, all checks green.
