Implementation Specification

Office & SharePoint
Integration

First-class Microsoft Office format comparison with optional SharePoint cloud sync — bringing Word, PowerPoint, and Excel into the same local-first diff workspace as code, images, and Git changes.

Overview

What This Is

This specification defines two additive features for the Diff Tool:

  1. Office document diff — Compare .docx, .pptx, and .xlsx files natively, without Microsoft Office installed. Uses the Open Packaging Convention (zip + XML) to extract and compare structured document content.
  2. SharePoint sync — Connect to SharePoint Online document libraries via Microsoft Graph API, browse files, compare document versions, and diff server copies against local files.

Product USP

Most diff tools (Kaleidoscope, Beyond Compare, Araxis, DeltaWalker, P4Merge) do not touch Office formats or SharePoint at all. Office comparison tools are either Windows-only, legal-document focused, Excel-only, or cloud/API-first. This tool differentiates by:

  • Universal workspace — Code, folders, images, Office docs, and SharePoint libraries in one review tool.
  • Local-first, no Office required — Unpack and compare Office files natively.
  • SharePoint-aware — Version history diff, server-vs-local comparison, collaboration review queues.
  • Machine-readable output — Structured JSON diff models that feed CI, agents, and AI enrichment pipelines.

Office Document Diff

How It Works

Modern Office files (.docx, .pptx, .xlsx) are zip archives containing XML parts. The office-adapter crate:

  1. Detects format from file extension and zip signature.
  2. Unpacks the zip archive with safety limits (size, part count).
  3. Parses relevant XML parts into structured document models.
  4. Compares left and right models section-by-section using diff-core for text, plus structural comparison for sections, slides, and sheets.
  5. Emits a deterministic OfficeDiffResult.

No Microsoft Office installation is required. No network access. Fully offline.

Supported Formats In Detail

Word (.docx)

Paragraph text, heading levels 1–9 and document outline, table cell contents with merged cell detection, comment text with author and anchor location, tracked changes presence detection, header/footer text per section, footnote/endnote text, embedded image presence and dimensions (content hash only, no pixel diff).

V1 outputs a structured change list, not a pixel-perfect redline. The model captures what changed (paragraph 3 text modified, table 2 row added, heading "Overview" → "Summary") rather than producing a formatted redline .docx.

PowerPoint (.pptx)

Slide addition, deletion, and reordering with structural diff. Title text, speaker notes, text box contents (multi-paragraph), shape count and coarse geometry, image presence/size/hash, table text, chart presence and source data summary.

V1 shows slide-level cards with text and metadata. Visual thumbnails are planned for a later milestone.

Excel (.xlsx)

Sheet additions, deletions, renames, and reordering. Used range dimensions, cell values (string, number, boolean, date), formula text, cell comments and notes, named ranges (name, scope, reference), row/column insertions and deletions, basic formatting detection if cheap to extract.

V1 must support sheet and range filters so large workbooks do not force a full comparison: --sheet Sheet1 --range A1:Z100.

Core Data Model

Top-level types
pub enum OfficeFormat { Word, PowerPoint, Excel }

pub struct OfficeDiffRequest {
    pub left: PathBuf,
    pub right: PathBuf,
    pub format: OfficeFormat,
    pub options: OfficeDiffOptions,
}

pub struct OfficeDiffResult {
    pub format: OfficeFormat,
    pub summary: OfficeDiffSummary,
    pub sections: Vec<OfficeSectionDiff>,
    pub warnings: Vec<String>,
    pub unsupported_features: Vec<String>,
}

pub struct OfficeSectionDiff {
    pub id: String,
    pub label: String,
    pub kind: OfficeSectionKind,
    pub status: ChangeStatus,         // Added | Deleted | Modified | Unchanged | Reordered
    pub changes: Vec<OfficeAtomicChange>,
}

pub struct OfficeAtomicChange {
    pub path: String,                 // e.g., "row=5,col=C", "slide=3,shape=title"
    pub kind: OfficeAtomicChangeKind, // TextChanged | FormulaChanged | SlideReordered | ...
    pub before: Option<String>,
    pub after: Option<String>,
    pub metadata: serde_json::Value,  // Format-specific enrichment
}

Safety Guarantees

  • Zip bomb protection: max_part_size (default 50 MB), max_part_count (default 10,000 parts), total uncompressed limit of 200 MB.
  • Streaming extraction: XML parts streamed rather than fully buffered in memory.
  • Image hashing: Embedded media hashed incrementally without loading full binary into memory.
  • XML safety: Entity expansion disabled (Billion Laughs attack prevented).

SharePoint Sync

User Stories

Browse and Compare

A user opens the SharePoint browser in the app, navigates to a document library, selects two files (or two versions of the same file), and sees a structured diff — all without leaving the tool.

Version History Diff

A document with 15 versions in SharePoint. The user picks versions 7 and 14, the tool fetches both (caching for reuse), diffs them, and displays what changed.

Server-vs-Local Diff

A user has been editing a local .docx. They connect to SharePoint, find the same document, and diff their local copy against the latest server version. If both have changed, the tool flags a potential conflict.

Review Queue

A "Shared With Me" view showing documents recently modified by teammates. Click to see what changed since last viewed.

Authentication

OAuth 2.0 with PKCE via Microsoft Identity Platform. Supports personal Microsoft accounts (common endpoint) and organizational/Entra ID accounts.

Account TypeV1 Support

Token Storage

Access tokens stored in memory only (1-hour lifetime). Refresh tokens stored in OS keychain via the keyring crate — same mechanism as planned AI BYOK keys. Never stored in settings JSON, localStorage, or source files.

File Caching

~/.cache/dt/sharepoint/
  {site-id}/
    {drive-id}/
      {item-id}/
        v{version-id}.docx
        v{version-id}.meta.json

Cache key = SHA256(site_id + drive_id + item_id + version_id). TTL = 24 hours (configurable). Max 500 MB with LRU eviction. Manual clear from Settings.

Security Review Checklist

  • OAuth PKCE with system browser — no embedded webview for auth
  • Access tokens never logged or serialized to disk
  • Refresh tokens stored exclusively in OS keychain
  • Zip bomb protection tested with adversarial fixtures
  • XML entity expansion disabled
  • SharePoint cache files use restrictive permissions (0600)
  • No SharePoint data proxied through third-party services
  • Rate limiting honored with Retry-After header parsing

Implementation Plan

Phase 1: Office Adapter Foundation

~3–4 weeks   New crate, no dependencies

Format detection, safe zip reading, and structured text extraction for Word, PowerPoint, and Excel. Unit tests for format detection and zip safety. Integration tests with hand-authored minimal .docx, .pptx, .xlsx.

Phase 2: Office Comparison Engine

~2–3 weeks   Depends on Phase 1

Section matching, text comparison via diff-core, structural comparison (added/deleted/reordered), Excel formula and named range comparison, image metadata comparison, fixture-driven tests with expected JSON output, performance test for large Excel workbooks with range filters.

Phase 3: CLI and Desktop Integration

~2–3 weeks   Depends on Phase 2

dt office subcommand with JSON and human modes, --sheet and --range flags, CLI snapshot tests, compare_office_files Tauri command, <OfficeDiffPane> React component with format-specific navigation, desktop UI smoke tests.

Phase 4: SharePoint Adapter Foundation

~3–4 weeks   Depends on Phase 2

OAuth 2.0 PKCE flow with system browser, token storage in OS keychain, Microsoft Graph API HTTP client, site/drive/file browsing, <SharePointBrowser> React component, "Connect SharePoint" settings flow, unit tests with mocked Graph API responses, integration test with real tenant (opt-in).

Phase 5: SharePoint Version Diff

~2–3 weeks   Depends on Phase 4

Version history listing, file download for specific versions, local file cache with hash-keyed storage and TTL, version-to-version diff, local-vs-server diff, cache eviction (LRU, max size), version picker UI, CLI commands for dt sharepoint diff and dt sharepoint diff-local.

Phase 6: Collaboration Features

~2–3 weeks   Depends on Phase 5 + AI adapter

Shared With Me / recent collaborator changes view, check-out status detection, local-vs-server conflict detection with 3-way merge, AI-powered summaries for SharePoint diffs, risk scoring for Office document changes, onboarding tooltips and usage documentation.

Design Notes

These notes extend the Editorial Diff design language. All UI should feel consistent with the existing code diff and folder compare modes — paper-like surfaces, strong typographic hierarchy, restrained color, compact controls.

Word Diff

Layout: Two-column reading layout. Left sidebar shows the document outline (heading tree). Main area shows change cards in reading order. Right margin has an annotations rail with change markers. Each changed section appears as a card with section label, change badge, before/after text, and table changes rendered as compact grids.

PowerPoint Diff

Layout: Slide rail on the left (thumbnail-sized cards with slide numbers and change badges). Main area shows selected slide changes in detail. Slide cards show title, change badge, and mini summary. Detail view shows title change, text box changes labeled by shape name, and collapsible speaker notes. Reordering indicated by arrow or position badge.

Excel Diff

Layout: Sheet picker tabs at top with change count badges. Below, document-like table view showing only changed cells in a compact grid. Each cell shows address (e.g., "C12") and value change. Formula changes have distinct highlighting. Row/column insertions shown as structural annotations. Range filter bar for scoping comparison to specific regions.

SharePoint Browser

Layout: Slide-out panel or left-side pane replacing the file tree. Three-level hierarchy: Sites → Drives → Files. Status indicator shows connection health. Version picker displays as a timeline or compact list with major/minor version distinction. Two selected versions enable the compare button.

Typography

  • Word text: Serif or serif-like display face — manuscript/proofing sheet feel.
  • PowerPoint titles: Larger, bolder weight for slide headings.
  • Excel cells: Monospace for values and formulas. Tabular number alignment.
  • SharePoint metadata: Sans-serif for UI chrome — compact and scannable.

Motion

Restrained and editorial. Slide cards reveal top-to-bottom with stagger. Section expansion uses height transitions. SharePoint browser slides in as a left drawer. Change cards highlight briefly when scrolled to. No bouncy or playful animations.
